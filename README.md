## Plan de développement

Le [cahier des charges](docs/development-plan.md) fixe l'ordre des phases. Voir l'[audit initial](docs/phase-0-audit.md), le [filtrage 84.1](docs/phase-84-1.md), le [branchement Matching 84.2](docs/phase-84-2.md), le [classement borné 84.3](docs/phase-84-3.md) et le [scoring configurable 84.4](docs/phase-84-4.md). La migration Matching de 84.4 doit être appliquée avant d'utiliser les nouveaux binaires sur une base existante.

Pour démarrer la topologie locale complète sous Windows 11, suivre le [guide d'installation](docs/windows-install.md), consulter le [diagramme d'architecture](docs/architecture.md) et utiliser le [guide des tests](docs/testing.md) pour les vérifications locales.

La documentation du microservice [Profile](docs/profile.md) couvre ses routes, son authentification et son canal d'import depuis Documents. Le livrable de cette tranche est décrit dans [phase 97.3](docs/phase-97-3.md).

Les [documents OpenAPI](docs/openapi.md) donnent les URLs locales de développement des contrats générés par les sept APIs métier ; la configuration des trois derniers services est décrite dans [phase 97.4](docs/phase-97-4.md).

Les [schémas PostgreSQL](docs/database-schemas.md) et le [guide des migrations EF Core](docs/migrations.md) résument les huit bases persistantes et leur procédure de mise à jour ; voir le bilan [phase 97.5](docs/phase-97-5.md).

Le [guide des événements asynchrones](docs/events.md) décrit les contrats Collection et Job, le consommateur Matching, les garanties de livraison et les vérifications en lecture seule ; voir [phase 97.6](docs/phase-97-6.md).

Le [guide de sécurité](docs/security.md), le [guide de dépannage local](docs/troubleshooting.md) et la [checklist V1](docs/v1-readiness.md) cadrent la prochaine validation ; voir le bilan [phase 97.7](docs/phase-97-7.md).

La [phase 97.8](docs/phase-97-8.md) consigne le contrôle V1 local : 1 048 tests unitaires backend, 610 intégrations, 68 tests Angular et 19 tests Chromium réussis. La CI sur le commit livré reste requise.

La [phase 97.9](docs/phase-97-9.md) actualise l’audit de préparation : les APIs candidat filtrent les données par propriétaire et les tests d’accès croisé existent ; l’attribution des données historiques et une validation OIDC multi-compte restent à démontrer avant déploiement.
La [phase 97.10](docs/phase-97-10.md) ajoute le scénario navigateur d’inscription candidat avec antiforgery ; il passe en Chromium avec Gateway simulé. La migration de la base locale et une inscription réelle restent à valider.
La [phase 97.11](docs/phase-97-11.md) fait réutiliser la base PostgreSQL Agents de la pile Compose principale par le démarrage local Ollama, pour éviter de créer une seconde base dans un autre projet.
La [phase 97.12](docs/phase-97-12.md) fournit une factory EF et une commande locale pour appliquer les migrations Identity sans démarrer le Gateway ; voir [l’installation Windows](docs/windows-install.md).
La [phase 97.13](docs/phase-97-13.md) configure les certificats persistants OpenIddict hors développement ; la [phase 97.14](docs/phase-97-14.md) ajoute le chevauchement des anciennes et nouvelles clés pendant leur rotation ; la [phase 97.15](docs/phase-97-15.md) permet de lire les mots de passe PFX depuis des fichiers secrets ; la [phase 97.16](docs/phase-97-16.md) ajoute les sauvegardes PostgreSQL et un contrôle de restauration isolé ; la [phase 97.17](docs/phase-97-17.md) automatise les migrations locales des huit bases ; la [phase 97.18](docs/phase-97-18.md) vérifie dans la CI le démarrage des bases et de RabbitMQ ; la [phase 97.19](docs/phase-97-19.md) ajoute l'application des migrations et le smoke test de la pile complète ; la [phase 97.20](docs/phase-97-20.md) teste inscription et reconnexion réelles via le navigateur ; la [phase 97.21](docs/phase-97-21.md) répète les sauvegardes et restaurations PostgreSQL sur le runner CI ; la [phase 97.22](docs/phase-97-22.md) répète également la restauration du volume RabbitMQ dans un broker temporaire ; la [phase 97.23](docs/phase-97-23.md) vérifie la compatibilité de la migration Identity avec Windows PowerShell 5.1 ; la [phase 97.24](docs/phase-97-24.md) permet de promouvoir une archive PostgreSQL vérifiée tout en gardant la base remplacée pour un retour arrière ; la [phase 97.25](docs/phase-97-25.md) ajoute un générateur local de certificats OpenIddict et son contrôle CI sous Windows PowerShell 5.1.
La [phase 97.26](docs/phase-97-26.md) regroupe les sauvegardes des huit bases et de RabbitMQ, vérifie leur restauration isolée et répète la restauration PostgreSQL dans la CI éphémère.
La [phase 97.27](docs/phase-97-27.md) restaure les huit bases et active le broker depuis un nouveau volume avec son image et son identité de nœud sauvegardées.
La [phase 97.28](docs/phase-97-28.md) attribue de façon contrôlée le profil historique resté sans propriétaire après migration ; la [phase 97.29](docs/phase-97-29.md) inventorie les propriétaires des données locales en lecture seule ; la [phase 97.30](docs/phase-97-30.md) exerce l'isolation de deux comptes via la pile Compose de CI ; la [phase 97.31](docs/phase-97-31.md) permet à un nouveau candidat de créer son profil depuis le navigateur ; la [phase 97.32](docs/phase-97-32.md) fiabilise l'initialisation Identity et les healthchecks des images API locales.
